## 2. การตั้งค่า

แก้ที่ `CONFIG` บนสุดของ `<script>` ในไฟล์ ที่เดียว

```js
const CONFIG = {
  SHEET_ID: "1He7E2jYJrmUP4CVhcSLa3dSLPOpG08R0rdRiQoprOJo",
  GID: "0",              // แท็บที่เก็บคำตอบจากฟอร์ม
  TEST_ROW_SKIP: 4,      // ตัดแถวข้อมูลแรกกี่แถวทิ้ง (แถวที่ลองกรอกตอนเทสฟอร์ม)
  TEST_NAME_PATTERN: /test|เทสต?ฟอร์ม|ทดสอบ/i,
  SET_PRICE: 899,
  SET_INCLUDES_CUP: true // เซต 899 บาท รวมแก้วเมลามีน 1 ใบ
};
```

ทดลองค่าอื่นได้จาก URL โดยไม่ต้องแก้ไฟล์ เช่น `?gid=123456789` หรือ `?skip=0`

**ชีทต้องแชร์แบบ "ทุกคนที่มีลิงก์ · ผู้อ่าน"** ไม่งั้นหน้าเว็บดึงข้อมูลไม่ได้
หน้าเว็บอ่านผ่าน gviz endpoint ของ Google ซึ่งเป็น read-only เขียนกลับไปที่ชีทไม่ได้

## 3. หน้านี้อ่านชีทยังไง

### จับคู่คอลัมน์ด้วยข้อความ ไม่ใช่ตำแหน่ง

ฟอร์มถูกแก้มาแล้วหลายรอบ ทำให้ชีทมีคอลัมน์ซ้ำชื่อและมีคอลัมน์ "ชุด ที่ 2–5" โผล่ไปอยู่ท้ายตาราง
ถ้าโปรแกรมอ่านตามตำแหน่งคอลัมน์ (A, B, C…) พอฟอร์มถูกแก้อีกรอบตัวเลขจะเพี้ยนทันทีโดยไม่มีอะไรเตือน

หน้านี้จึงจับคู่จาก **ข้อความในหัวคอลัมน์** แทน เช่นคอลัมน์ไหนก็ตามที่หัวมีคำว่า
`กล่องข้าว` และ `ชมพู` จะถูกนับเป็นกล่องข้าวสีชมพู ไม่ว่าคอลัมน์นั้นจะย้ายไปอยู่ตรงไหน
ถ้ามีคอลัมน์ที่จับคู่ไม่ได้เลย หน้าเว็บจะแจ้งไว้ในหัวข้อตรวจสอบความถูกต้อง

รายการที่จับคู่ไว้อยู่ในตัวแปร `ITEMS` ถ้าเพิ่มสินค้าใหม่ในฟอร์ม ให้เพิ่มบรรทัดใน `ITEMS` ด้วย

### อ่านจำนวนและราคา

ช่องในชีทเก็บเป็นข้อความแบบ `3 ใบ (ราคา 150 บาท)` จึงดึงตัวเลขสองตัวออกมา

- จำนวน จาก `(\d+) ใบ`
- ราคา จาก `ราคา (\d+) บาท` รองรับทั้ง `120 บาท` และ `120บาท` และตัวเลขมีคอมมา เช่น `1,036`

**ใช้ราคาที่ระบุในชีทเป็นหลัก ไม่ใช่ จำนวน × ราคาต่อชิ้น** เพราะมีโปรโมชั่นสติกเกอร์ 2 ใบ 100 บาท
ถ้าคิดจากราคาต่อชิ้นจะได้ยอดเกินจริง ส่วนต่างนี้แสดงไว้ใต้ตารางยอดเงิน

### เซตปิคนิค

- คอลัมน์ `เซตปิคนิคพร้อมลุย` บอก **จำนวนเซตที่สั่งและเงินที่จ่าย** เช่น `2 set (ราคา 1,798 บาท)`
- คอลัมน์ `ชุด ที่ 1–5` บอก **สีที่เลือกของแต่ละเซต** หนึ่งช่องเท่ากับหนึ่งเซต
- จำนวนของที่ต้องสั่ง นับจาก **ช่องเลือกสี** เพราะสีคือสิ่งที่ต้องไปสั่งโรงงาน
- ยอดเงิน คิดจาก **จำนวนเซตที่แจ้ง** เพราะนั่นคือเงินที่โอนมาจริง
- ถ้าสองอย่างนี้ไม่เท่ากัน หน้าเว็บจะขึ้นเตือนพร้อมบอกว่าแถวไหน ต้องโทรถามเจ้าตัว

ถุงผ้าที่มากับเซตเลือกได้แค่สีผ้า ส่วนลายบนถุงเป็นแบบสุ่ม (แจ้งไว้ในฟอร์มแล้ว)
จึงแยกเป็นบรรทัด "จากเซต (ลายสุ่ม)" ต่างหาก ไม่ปนกับถุง 4 แบบที่คนสั่งแยกเลือกลายเอง

### รวมตามเบอร์โทร

ตัดอักขระที่ไม่ใช่ตัวเลขออกก่อนเทียบ เพราะมีบางเบอร์ที่ติด zero-width space มาจากการ copy
คนที่สั่งหลายรอบด้วยเบอร์เดียวกันจะถูกรวมเป็นรายการเดียว และบอกไว้ว่ามาจากแถวไหนบ้าง

### สลิปโอนเงิน

ชีทเก็บเป็นลิงก์แบบ `https://drive.google.com/open?id=XXXX` หน้าเว็บดึง id ออกมาแล้วแสดงสองอย่าง

- รูปตัวอย่างแบบ auto-load ผ่าน `drive.google.com/thumbnail?id=…`
- กดที่รูปเพื่อเปิดไฟล์เต็มที่ `drive.google.com/file/d/…/view`

ถ้าโฟลเดอร์ปลายทางไม่ได้แชร์ รูปจะโหลดไม่ขึ้นและเปลี่ยนเป็นลิงก์ให้กดแทน
ปิดการโหลดรูปอัตโนมัติได้ที่ checkbox "แสดงสลิปอัตโนมัติ"

## 4. การตรวจว่าตัวเลขบนหน้าเว็บตรงกับชีทจริง

นี่คือส่วนสำคัญที่สุดของหน้านี้ ตัวเลขที่เอาไปสั่งของและเก็บเงินต้องเชื่อได้

### หน้าเว็บตรวจให้อัตโนมัติ

โค้ดนับยอด **สองทางที่เขียนแยกกันคนละชุด** แล้วเอามาเทียบกัน

1. `tally()` เดินจากออร์เดอร์ที่ประกอบเป็น object แล้ว — ผ่านการแยกเซต แยกชิ้น จับกลุ่ม
2. `rawRecount()` เดินจากตารางดิบทีละช่อง ดึงตัวเลขตัวแรกที่เจอในแต่ละช่องมาบวกกันตรง ๆ

ถ้าตรรกะฝั่งใดฝั่งหนึ่งมีบั๊ก ตัวเลขสองทางจะไม่ตรงกันและตราจะขึ้นสีแดงว่า "ไม่ตรงกัน"
ทั้งหมดที่ตรวจมี 8 ข้อ

| # | ตรวจอะไร | ไม่ผ่านแล้วแปลว่า |
|---|---|---|
| 1 | แถวในชีท = ออร์เดอร์จริง + แถวทดสอบ + แถวว่าง | มีแถวหายไประหว่างทาง |
| 2 | จำนวนชิ้นที่สั่งแยก นับสองทางตรงกัน | บั๊กในการจับคู่คอลัมน์หรือการแยกเซต |
| 3 | จำนวนเซต นับสองทางตรงกัน | อ่านคอลัมน์เซตผิด |
| 4 | จำนวนช่องเลือกสี = จำนวนเซตที่สั่ง | มีคนกรอกสีเกินหรือขาด ต้องโทรถาม |
| 5 | ยอดเงิน นับสองทางตรงกัน | บั๊กในการรวมเงิน |
| 6 | ช่องที่มีข้อมูลทุกช่อง อ่านออกครบ | มีคนพิมพ์รูปแบบแปลก ๆ ลงในฟอร์ม |
| 7 | ทุกคอลัมน์ในชีทถูกจับคู่ | ฟอร์มมีคำถามใหม่ที่ยังไม่ได้เพิ่มใน `ITEMS` |
| 8 | แก้วจากเซต = จำนวนชุดสีที่กรอก | ค่า `SET_INCLUDES_CUP` ไม่สอดคล้องกับที่ประกาศไว้ในโปสเตอร์ |

ข้อ 4 เป็นสีเหลือง ไม่ใช่สีแดง เพราะเป็นความคลาดเคลื่อนของคนกรอก ไม่ใช่บั๊กของโปรแกรม

### ตรวจด้วยมืออีกรอบ ก่อนสั่งของจริง

ตราสีเขียวบอกได้แค่ว่า "โปรแกรมนับตรงกับตัวเอง" ยังไม่ได้บอกว่าตรงกับชีท
ก่อนกดสั่งของจริง ควรตรวจด้วยมือหนึ่งรอบตามนี้

1. กาง **ดูยอดดิบรายคอลัมน์** ในหัวข้อตรวจสอบความถูกต้อง ตารางนี้เรียงตามคอลัมน์จริงในชีท
   และแยกให้สามช่อง คือ `รวมทั้งชีท` (บวกทุกแถวรวมแถวทดสอบ) `แถวทดสอบ` (ส่วนที่ถูกหักออก)
   และ `ใช้จริง` (ยอดที่หน้าเว็บแสดง) ถ้าบวกคอลัมน์ในชีทเองด้วยตา ตัวเลขจะตรงกับช่อง `รวมทั้งชีท`
   ไม่ใช่ `ใช้จริง` เพราะการบวกด้วยตามักจะรวมแถว 2–5 ที่เป็นแถวทดสอบเข้าไปด้วย
2. เปิดชีท เลือกทั้งคอลัมน์ของสินค้าที่จะเช็ก เช่นคอลัมน์ `กล่องข้าว สีชมพู`
3. ที่ช่องว่างข้างล่าง ใส่สูตรนี้เพื่อบวกจำนวนใบจากทุกแถว โดยข้ามแถวทดสอบ 4 แถวแรก

   ```
   =SUMPRODUCT(IFERROR(VALUE(REGEXEXTRACT(N6:N, "^\d+")),0))
   ```

   เปลี่ยน `N6:N` เป็นคอลัมน์ที่ต้องการ แถวเริ่มที่ 6 เพราะแถว 2–5 เป็นแถวทดสอบ
4. ตัวเลขที่ได้ต้องเท่ากับช่อง "จำนวนชิ้น" ของคอลัมน์นั้นในตารางยอดดิบ
5. เช็กสัก 3–4 คอลัมน์ก็พอ ถ้าตรงหมดแปลว่าทั้งท่ออ่านชีทถูกต้อง

ถ้าตัวเลขไม่ตรง อย่าเพิ่งสั่งของ ให้ดูก่อนว่าแถวทดสอบถูกตัดตรงกันหรือเปล่า
`TEST_ROW_SKIP` ปัจจุบันคือ 4 ถ้ามีคนไปลบหรือเพิ่มแถวทดสอบในชีท ต้องแก้ค่านี้ด้วย
รายชื่อแถวที่ถูกตัดออกแสดงไว้ในข้อ 1 ของหัวข้อตรวจสอบความถูกต้องแล้ว

## 5. แก้ไขและ deploy

ไฟล์เดียว ไม่มี dependency แก้แล้วเปิดในเบราว์เซอร์ดูได้เลย

### publish ขึ้นเว็บ

repo คือ `tsripata/thor-events` เสิร์ฟผ่าน GitHub Pages ทุกอย่างที่ push ขึ้น `main`
จะเปิดดูได้แบบสาธารณะภายในไม่กี่นาที

GitHub token เก็บไว้ในไฟล์ในเครื่อง **ห้าม commit ค่าตัว token ลง repo เด็ดขาด**

```bash
# token อยู่ในไฟล์ในเครื่อง ไม่ได้อยู่ใน repo
GITHUB_TOKEN=$(cat ~/.github_token)

git add market/
git commit -m "Update order summary"
git push "https://x-access-token:${GITHUB_TOKEN}@github.com/tsripata/thor-events.git" main
```

`.gitignore` มี `.github_token` อยู่แล้ว เพื่อกันการเผลอ `git add .`
ถ้า token เคยหลุดไปที่ไหนก็ตาม ให้ไป revoke แล้วสร้างใหม่ที่
GitHub → Settings → Developer settings → Fine-grained tokens

### ข้อควรระวังเรื่องข้อมูลส่วนตัว

หน้านี้แสดง **ชื่อ เบอร์โทร และสลิปโอนเงิน** ของผู้ปกครอง และ GitHub Pages เป็นเว็บสาธารณะ
ใครที่เดา URL ถูกก็เปิดดูได้ มาตรการที่ใส่ไว้แล้วคือ

- `<meta name="robots" content="noindex, nofollow, noarchive">` ในหน้า
- `robots.txt` ที่ root ของ repo สั่ง `Disallow: /market/`
- ไม่มีลิงก์จากหน้าแรกของเว็บมาที่หน้านี้

ทั้งหมดนี้กันไม่ให้ search engine เก็บ แต่**ไม่ได้กันคนที่รู้ URL**
ถ้าต้องการกันจริงจัง ทางเลือกคือเปลี่ยนชื่อไฟล์เป็นอะไรที่เดาไม่ถูก
หรือย้ายไปเปิดเป็นไฟล์ในเครื่องแทนการ publish
